# 中国城市行程规划

把用户的一句话目标转换为可审校的结构化行程草案。当前演示知识库覆盖上海、杭州、苏州；超出范围时明确能力边界，不拼接无关城市资料。

## 工作流

1. 提取目的地、天数、人数、总预算、兴趣、节奏和特殊约束。缺失字段采用保守默认值，并在成品中列出假设。
2. 将任务拆为天气查询、知识检索、景点编排、预算分配和质量审校。天气只有当前实况时，不伪装成多日预报。
3. 使用旅行 RAG 获取目的地景点和稳定规则。知识块标识仅用于内部校验，不写入用户文档。
4. 每天安排一至两个核心活动，优先同区域组合；抵离日降低强度。雨天优先室内候选，仍给出替换项。
5. 预算必须包含住宿、餐饮、市内交通、门票和机动金；用户未说明时，预算按目的地落地支出估算，不包含往返大交通。
6. 将草案交给 `travel-plan-review`。存在 ERROR 时按问题代码定向修改，最多两轮；仍不通过时输出可行部分和明确限制。
7. 将完整成品输出为 UTF-8 Markdown 附件；聊天正文只发送简短的文件通知。动态数据限制统一放在文档末尾。

输出字段及默认规则见 [references/contract.md](references/contract.md)。来源和本地化说明见 [references/sources.md](references/sources.md)。

## 边界

- 不宣称已经订票、订房或确认实时库存。
- 不把估算价格、当前天气延伸为未来确定事实。
- 不因字段缺失反复追问；对 Demo 可安全推断的字段直接注明假设。
- 无法满足预算或时间约束时，指出不可行原因并给出最小调整量。
